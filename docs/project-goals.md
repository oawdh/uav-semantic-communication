# 项目目标与探索路线

## 总目标

构建一个语义驱动的无人机交互原型：在噪声、弱连接、模糊指令和动态环境下，系统能够恢复用户意图、映射为安全动作，并用实验指标证明语义链路相对传统指令链路的优势。

## 北极星演示

学生最终要完成一个可解释的演示：

> 操作者说“飞到红色目标附近，保持安全距离并拍照”。系统解析意图，结合视觉目标与安全边界，调用 MCP 工具完成无人机动作。如果置信度不足或存在安全冲突，系统拒绝执行并请求澄清。

## 阶段目标

### M0 知识库启动

产出：
- 读完综述的摘要页和 3 个核心概念页。
- 能讲清“语义通信”和“无人机语义安全”的区别与联系。
- 每位同学至少提交一次 wiki 修订。

验收：
- `python3 scripts/lint_wiki.py .` 无严重死链。
- `wiki/index.md` 能索引到所有新增页面。

### M1 无人机基础控制闭环

产出：
- 使用 Tello 或模拟器完成起飞、降落、平移、旋转、拍照。
- 建立动作 API 草案：`takeoff`、`land`、`move`、`rotate`、`capture_image`、`emergency_stop`。

验收：
- 每个动作有最小 demo。
- 记录失败模式：连接失败、低电量、指令超时、障碍物风险。

### M2 语音/文本到意图 JSON

产出：
- 将自然语言指令解析为结构化意图。
- 设计任务标签和槽位，例如 `action`、`target`、`distance`、`direction`、`safety_constraint`。

验收：
- 20 条测试指令的解析结果可人工检查。
- 低置信度时输出 `ask_clarification`，而不是硬执行。

### M3 MCP 语义适配器

产出：
- 将意图 JSON 映射为 MCP 工具调用。
- 将无人机状态暴露为 MCP Resources，例如电池、高度、速度、图像帧、障碍物状态。

验收：
- 至少 5 个工具可被本地客户端调用。
- 所有危险动作前检查安全约束。

### M4 视觉 grounding

产出：
- 将“红色目标”“灭火器”“那边”等语义与图像区域或空间目标关联。
- 给出目标置信度与候选目标列表。

验收：
- 至少完成一个静态图像 demo 和一个视频帧 demo。
- 目标不存在或置信度低时不会盲目飞行。

### M5 语义鲁棒性实验

产出：
- 构建噪声、丢包、低带宽或 ASR 错误场景。
- 对比传统命令链路与语义意图链路。

验收指标：
- 意图执行成功率。
- 端到端延迟。
- 平均交互轮次。
- 安全拒绝率与误拒绝率。
- 单任务传输负载或 token/bit 开销。

## 适合学生认领的小题目

- 设计 30 条无人机自然语言指令数据集。
- 实现 `intent_schema.json` 并写解析评测脚本。
- 复现 `drone-mcp` 的最小工具封装。
- 用模拟噪声测试 Whisper/Faster-Whisper 的意图保持率。
- 设计“语义熔断”规则：什么情况下必须反问、拒绝或返航。
- 比较 YOLO、CLIP、MobileSAM 在目标 grounding 中的角色。
- 把一次失败实验写成 wiki 页面：失败原因、复现实验、下一步。

## 选题原则

一个好任务应该同时满足：

- 能在 1 到 2 周内做出可展示结果。
- 有明确输入、输出和指标。
- 能写回知识库，帮助下一位同学少走一步弯路。
- 即使失败，也能产生有价值的错误分析。
